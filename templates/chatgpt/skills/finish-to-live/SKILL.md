# Finish to LIVE (ChatGPT-first, Work-capable)

Outcome = original requested behavior VERIFIED on the real production URL; a pending CI, merged PR, preview READY or a single attempted repair is NOT success. Use ChatGPT Work for lengthy cloud-browser/computer tasks when available; otherwise use connected ChatGPT tools only within actual execution availability. Never claim an unstarted Work task runs later.

1. Recover current project, original acceptance criteria and EXISTING root/PR (no duplicate), base/source HEAD, owner and leases, required exact-HEAD checks, production alias. Read repo AGENTS.md and canonical spec: https://github.com/andylitvinov-design/ai-projects-brain/blob/main/agent-skills/finish-to-live.md
2. Prove a causal current-HEAD failure from actual CI job/source, semantic conflict, authorized merge/approval, deployment or live behavior. Queued checks are WAIT, not FAIL.
3. Repair verified defects in small cohesive batches, add regression, run real focused tests. Apply https://github.com/andylitvinov-design/ai-projects-brain/blob/main/systems/pr-one-publish-standard.md . Do not push file-by-file, force/empty commit, rerun unchanged CI, or bypass protected Core/Specialist/Guard, privacy/consent/payments/security or cost guards.
4. Freeze HEAD during mandatory CI. If a new failure appears, repeat diagnosis -> repair on same root; if legitimate CI is pending, checkpoint WAIT_CI and let an existing authorized worker/Work continue when actually configured.
5. Protected native merge only with approvals/lease/checks. Correlate merge SHA to production deploy SHA/ancestry and test the requested functionality on actual LIVE. A LIVE failure repeats the same causal repair loop.
6. Persist checkpoint: root/PR, exact SHA, job evidence, lease, last fix, next event/owner, deployment evidence. Holistic House has existing :10/:40/:30/:00 agents, which may be reused only for registered eligible work. No duplicate worker, paid service or unbounded no-op retry.
7. Final LIVE_VERIFIED only with URL, SHA, functional smoke and all acceptance checks. Otherwise report WAIT/BLOCKED/NO_CONTINUATION precisely; no false invisible background promise.

Questions about the command are explanation-only. Honor only-check/no-publish constraints.
