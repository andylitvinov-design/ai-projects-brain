# Report Client-Readiness Style Gate — Andrey Li Reports

This file is a mandatory addendum to `report-style-bible.md`, `report-quality-rubric.md`, and `report-style-auditor-instructions.md`.

It exists because a report can be methodically complete and still fail as a client report.

Main rule:

**Depth inside. Compression outside.**

The agent may think deeply. The client should receive only the useful living result.

---

## 1. Client-ready first

Before sending or approving any report, ask:

```md
Можно ли отправить этот текст клиенту как живое письмо Андрея?
```

If no, rewrite.

Do not approve the report only because it contains:

- Dao level;
- Wu Xing;
- bottleneck;
- hidden mechanism;
- support;
- safety note.

These are required, but not sufficient.

The report must feel like Andrey is checking the state now.

---

## 2. Depth inside, compression outside

The report should show only what helps the client:

- ясность;
- образ;
- bottleneck;
- опора;
- поддержка;
- следующий шаг;
- что проверить потом.

Delete anything that does not create clarity, support, or movement.

A paragraph is weak if it only explains the method.

A paragraph is strong if it makes the client understand:

```md
А, вот что со мной сейчас.
Вот где узел.
Вот что делать первым.
```

---

## 3. Compression rule

If the text can be shortened by 40%+ without losing meaning, it is not client-ready.

Signs of water:

- the same idea repeated in several sections;
- element theory before diagnosis;
- long lists where one sentence is enough;
- `Что значит...` blocks that restate the same point;
- long psychodynamic chains without practical consequence;
- full report structure built from minimal input.

Fix:

```md
Keep the strongest sentence.
Remove the explanation around it.
```

---

## 4. Bach-led Wu Xing reports

Use this when Bach essences are given as diagnostic signals for Wu Xing.

Do not start with textbook element descriptions.

Start with the state.

Good structure:

```md
Смотрю.
Здоровье 3.3.
Это Крепость / сжатость.

Главное здесь — ...

По Bach видно:
- Agrimony / Земля — ...
- Cherry Plum / Металл — ...
- Impatiens / Огонь — ...
- Beech / Дерево — ...

Ядро:
...

Поверхность:
...

Bottleneck:
...

Первый шаг:
...

Проверить через:
...
```

---

## 5. Main axis vs surface symptoms

When there are several remedies, separate layers.

Example:

```md
Agrimony + Cherry Plum = скрытое напряжение + контроль.
Beech + Impatiens = раздражение + ускорение.
Вода = needs verification.
Первый шаг = Земля, не рывок.
```

This is stronger than describing every remedy equally.

The client must know:

- what is central;
- what is surface;
- what is missing / needs verification;
- what to support first.

## 6. Bad vs good fragments

### Bad

```md
Дерево отвечает за рост, движение, инициативу, право действовать и способность идти вперёд.
```

### Good

```md
Дерево сжато.
Движение есть, но оно выходит раздражением.
```

---

### Bad

```md
Огонь отвечает за радость, контакт, живость, выражение, сердечное тепло и способность быть в процессе.
```

### Good

```md
Огонь ускорен.
Не тепло, а внутренний мотор.
```

---

### Bad

```md
В данном отчёте рассматривается методическая логика состояния здоровья 3.3.
```

### Good

```md
Смотрю.
Здоровье 3.3.
Главное здесь — сжатость.
```

## 7. Size rules by input

The size must match the input.

- Short / Bach note: 300–700 words.
- Deep / Full Support Snapshot: 600–1000 words.
- Full Client Report: 900–1400 words maximum, only with enough client data.
- Follow-Up Check Note: 120–300 words.
- Progress / Remedy Relevance Check: 250–600 words.

Minimal input cannot produce a Full Client Report.

Minimal input can produce:

- Short Remedy / Bach Decoder;
- Quick Resource Diagnosis;
- Deep / Full Support Snapshot, if Wu Xing and Dao are needed.

---

## 8. Internal QA must stay internal

Never include in client-facing report:

- `Quality check`;
- registry/source notes;
- `GitHub registry checked`;
- tool/source routing;
- auditor scoring;
- internal validation lists.

Client-facing text starts with the client state, not system process.

---

If a report is dry, inflated, or GPT-like, rewrite it toward this rhythm:

```md
Это ...

Главное здесь — ...

Как будто ...

По препаратам видно:
- ...

Ядро:
...

Bottleneck:
...

Сейчас задача не ...
А ...

Дальше:
...

Проверить через ...
```

Short.
Living.
Diagnostic.
No water.
